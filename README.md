# Analyst Simulator — структура проекта

## Папки
- `index.html` — главное меню / библиотека кейсов.
- `cases.js` — каталог доступных кейсов. При добавлении кейса добавьте одну запись в массив `cases`.
- `cases/` — отдельные HTML-файлы и сценарные JS-файлы кейсов.
- `engine/engine.js` — общие функции игрового движка (переходы между экранами, печать текста, безопасное JSON-сохранение).
- `engine/styles.css` — общий визуальный стиль.
- `images/` — общие изображения и спрайты.

## Как добавить кейс
1. Скопируйте `cases/hotel-commission.html` в `cases/my-new-case.html`.
2. Скопируйте `cases/hotel-commission.js` в `cases/my-new-case.js`.
3. В HTML замените подключение `hotel-commission.js` на `my-new-case.js` и обновите `<title>`.
4. Измените сценарий и логику в новом JS-файле. Не редактируйте общий `engine/`, если кейс использует существующие типы сцен.
5. Добавьте объект в массив `cases` в `cases.js`, указав `file: "cases/my-new-case.html"`.
6. Проверьте все переходы и ссылки на изображения в браузере.
7. Закоммитьте файлы в GitHub. GitHub Pages обслуживает статические HTML/CSS/JS напрямую.

## Важно
- Относительные ссылки из файлов внутри `cases/` на изображения начинаются с `../images/`.
- Общие стили подключаются как `../engine/styles.css`, общий runtime — `../engine/engine.js`.
- Текущий кейс пока сохраняет собственную сценарную логику в `cases/hotel-commission.js`. Это позволяет вынести новые кейсы в отдельные файлы без копирования CSS и базовых утилит. Следующий шаг при росте количества кейсов — постепенно переносить повторяющуюся механику выбора и характеристик в общий движок.
- Это первая миграция структуры; игровой сценарий не переписан в полностью data-driven формат, чтобы минимизировать риск сломать текущую игру.
